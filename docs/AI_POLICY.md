# AI Policy

While not agreeing that generative LLMs are "AI", we understand that is what most people are calling it, and so use the term in the same way for purpose of aiding contributors in finding our policy.

The areas below provide more details, but at a high level:

- Code must be understood, however it is created.
- Communication between humans should be human.
- Be kind, respect the intent and the individual.

## Code must be understood

Creators of a pull request should try to understand the code submitted. We recognize that even before LLMs, various experience levels meant differing levels of understanding of the programmer. Still, intent matters.

[Reviewers](./COLLABORATORS.md) accepting code **must** understand the code. While LLM agents may be able to identify problems in code, they never really consider if the change _should_ be made.

Do not include AI agents as a commit author.

## Text meant for humans

All text meant for humans to read should be written by a human. This includes issues, pull request descriptions, and comments (in code or PRs).

LLMs may help with translation, and while we don't encourage such use, if you do resort to them: write the full thought in the original language, and have the LLM provide a direct translation.

## Enforcement is based on respect

We do not desire to police people's personal tool usage. While templates may ask for author acceptance of the policy, failure to do so does not mean we automatically refuse to engage. We try to understand why not, given the time and energy we have. We also realize that an actual bug may be in there somewhere.

[Be kind](./CODE_OF_CONDUCT.md). Even when someone disregards this policy, there's no need to be unkind back.

Respecting this policy is another way to be kind. Do not assume that just because some tokens were spent and the code now exists that we must accept it. If collaborators close an issue or pull request, respect the decision. If you'd like to contribute again, try to learn from the principles in this policy.
